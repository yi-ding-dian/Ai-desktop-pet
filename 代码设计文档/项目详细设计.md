## 1. 总体架构

### 1.1 进程模型

```text
┌────────────────────────────────────────────────────────┐
│ Electron 主进程（Node/TS）                               │
│  · 窗口管理：透明 / 无边框 / 置顶 / 点击穿透 / 拖拽          │
│  · 平台适配层：Windows / Linux / macOS（实现可插拔，见 §5.1）  │
│  · Python 子进程管理：spawn / 握手 / 监控 / 重启 / 退出清理  │
│  · 托盘、全局快捷键、单例锁                                │
└──────────────┬─────────────────────────────────────────┘
               │ IPC（contextBridge 安全桥）
┌──────────────┴─────────────────────────────────────────┐
│ Electron 渲染进程（Chromium + React）                     │
│  · Live2D 渲染（独立渲染循环，不受 React 调度影响）           │
│  · 对话气泡 / 设置面板 / 语音播放                           │
│  · WS 客户端 SDK（重连 / 心跳 / 请求路由 / 二进制音频）        │
└──────────────┬─────────────────────────────────────────┘
               │ WebSocket  ws://127.0.0.1:<动态端口>
               │ JSON 事件帧 + 二进制音频帧
               │ hello 鉴权（token）/ 协议版本协商 / 心跳
┌──────────────┴─────────────────────────────────────────┐
│ Python 后端（FastAPI，由 Electron 拉起）                   │
│  · interfaces/ws  协议转换、连接管理、鉴权                   │
│  · application    对话流水线编排、会话管理                    │
│  · modules        character/chat/llm/memory/voice/behavior │
│  · shared         配置、路径、日志、错误码                    │
└────────────────────────────────────────────────────────┘
```

**核心原则**：
1. 渲染进程**永远不直接操作**窗口和子进程，一律走 IPC → 主进程（渲染进程保持"纯 UI"）。
2. 后端业务模块**永远不感知** WS 协议细节，协议转换只在 `interfaces/ws`。
3. 前端**永远不感知**具体 LLM 服务商差异，BYOK 配置只在后端 `modules/llm`。

### 1.2 开发态 / 生产态差异

| | 开发态 | 生产态 |
|---|---|---|
| 前端 | `electron-vite dev`（HMR） | 打包后的 dist |
| 后端 | Electron 直跑 `python -m backend.main` | 拉起 PyInstaller onedir 产物 |
| 窗口 | 带 devtools 调试 | 无 |
| 日志 | 控制台 + 文件 | 仅文件（用户目录） |

两种形态下**握手协议完全一致**（见 §3.4），保证开发与生产只差启动命令。

**依赖方向**（违反即评审不通过）：

```text
interfaces → application → modules → shared
```

- `modules/*` 之间禁止互相 import 内部实现；跨域需求（如 chat 用 llm 的流式接口）通过 `application/chat_pipeline.py` 编排。

## 3. WebSocket 通信协议（v1）

> 设计参考了同类开源项目 [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) 的实战经验（打断机制、逐句流式、emotion 字段）。

### 3.1 消息信封（JSON 文本帧）

```json
{
  "v": 1,
  "id": "msg-uuid",
  "reply_to": "msg-uuid | null",
  "type": "事件类型",
  "ts": 1730000000000,
  "data": { }
}
```

- `v`：协议版本，首版固定 `1`。
- `id`：发送方生成的消息 id；`reply_to` 用于响应配对（请求-响应型消息）。
- 流式推送类消息（token/emotion）不必等对方应答，`reply_to` 可空。

### 3.2 客户端 → 服务端 事件

| type | data | 说明 |
|---|---|---|
| `hello` | `{token, protocol_version, app_version, client_role?}` | 连接后**首条必须**，鉴权 + 版本协商；`client_role`=`pet`（缺省，接收行为/提醒推送）/`settings`（只收发配置），2026-10-18 |
| `user_message` | `{text, session_id?}` | 用户文字输入 |
| `interrupt` | `{}` | 打断：取消当前 LLM 流/TTS 播放 |
| `pet_event` | `{kind: "tap_head"/"drag_end"/"idle_touch", payload}` | 宠物交互事件（宠物能"感知"被摸） |
| `get_config` | `{}` | 拉取当前配置（不含 key 明文） |
| `set_config` | `{patch: {...}}` | 更新配置（含设置 LLM key 的专用字段） |
| `test_llm` | `{base_url, model, key?}` | 设置面板"测试连接" |
| `load_history` | `{session_id, limit}` | 拉取历史消息（气泡回填） |
| `list_characters` | `{}` | 请求角色包列表（manifest 元数据） |
| `switch_character` | `{character_id}` | 切换角色（前端重载模型 + 后端换人格） |
| `behavior_done` | `{id, interrupted}` | 行为执行完成/被中断回报（Phase 3） |
| `env_update` | `{work_area, window_pos, window_size}` | 环境上报：屏幕/窗口几何（行为决策依据） |
| `get_reminders` | `{limit?}` | 拉取未读提醒快照 + 未到期计划（提醒列表，2026-10-18） |
| `ack_reminders` | `{ids?, all?}` | 标记提醒已读（按事件 id 或全部），回 `reminders` 快照 |
| `get_reminder_history` | `{date?, limit?}` | 拉取时钟视图：当天事件（已读 + 未读）+ 所有未到期计划，按到期时间正序 |
| `delete_reminder_item` | `{id}` | 删除时钟视图一项：事件 id 删 `reminder_events` 记录；计划 id 删 `reminders`；回 `reminders` + `reminder_history` 刷新快照 |
| `memory_book_list` | `{kind?}` | 拉取记忆本条目（设置页/任意连接；回 `memory_book_items`） |
| `memory_book_save` | `{items: [{name?, kind?, value}]}` | 记忆本保存/同名更新（回 `memory_book_result` + `memory_book_items`） |
| `memory_book_rename` | `{old_name, new_name}` | 记忆本改名（回结果 + 列表快照） |
| `memory_book_delete` | `{names: [...]}` | 只删记忆本记录（不动磁盘文件；设置页按钮路径） |
| `memory_book_file_deleted` | `{path}` | 宠物面回传：主进程已确认删除真实文件 → 后端移除记录/清长期记忆 |
| `set_mode` | `{mode: "teach"/"normal"}` | 教学模式切换（P5）：影响后端提示词注入与行为引擎暂停 |
| `audio_chunk` | 二进制帧（Phase 2） | 语音输入（麦克风采样） |

### 3.3 服务端 → 客户端 事件

| type | data | 说明 |
|---|---|---|
| `hello_ack` | `{ok, session_id, server_version, protocol_version}` | 鉴权结果；`ok=false` 时伴随 `error` 后断开 |
| `state` | `{state: "idle"/"walking"/"sleeping"/"thinking"/"speaking"/"dragging"}` | 宠物状态机，驱动动画节奏与行为互斥 |
| `behavior` | `{id, name, params}` | 行为指令（Phase 3）：走动/睡眠/张望…（见 §4.5） |
| `reply_start` | `{message_id}` | 一轮回复开始 |
| `token` | `{message_id, text}` | 流式增量文本（气泡逐字渲染） |
| `sentence` | `{message_id, index, text}` | 分句完成（供 TTS 流水线/断句展示） |
| `emotion` | `{message_id, emotion, intensity}` | 情绪切换 → 前端表情/动作 |
| `audio` | 二进制帧（Phase 2） | TTS 音频块（头见 §3.5） |
| `reply_end` | `{message_id, full_text, interrupted?}` | 一轮回复结束 |
| `tool_call` | `{id, name, args}` | 工具调用（§4.7）：后端 → 前端执行（如 `open_settings` → 打开设置窗）；在对应回复 `reply_end` 之后推送 |
| `proactive` | `{message_id, text, emotion, kind?, batch_id?, items?, reminder_id?, due_at?, late?}` | 主动消息（问候/提醒），无对应用户输入；提醒 v1（2026-10-18）：`kind="reminder"`，同一轮到期的多条合并为 `items`，前端**无论语音开关都展示气泡**，语音只是附加音频帧 |
| `reminders` | `{items, unread_count, pending, pending_count}` | 未读提醒快照（get_reminders / ack_reminders 的响应）；item 含 `id / reminder_id / text / due_at / fired_at / late / acknowledged / pending / time_text`；`pending` 为未到期计划（灰灯展开用） |
| `reminder_history` | `{date, items, read_count, unread_count, pending_count}` | 时钟视图：当天事件（已读 + 未读）+ 所有未到期计划，按到期时间正序；未到期项 `pending=true` |
| `memory_book_items` | `{items, count}` | 记忆本列表快照（item 含 `id/name/kind/value/is_dir/path_exists/created_at/updated_at`） |
| `memory_book_result` | `{ok, code, message}` | 记忆本写操作结果（保存/改名/删记录/文件已删） |
| `history` | `{session_id, messages: [...]}` | 历史回填 |
| `characters` | `{list: [...], current}` | 角色包列表与当前角色（响应 list_characters） |
| `character_changed` | `{character_id}` | 角色切换完成确认 |
| `config` | `{...}` | 配置快照（key 以 `sk-****` 掩码返回） |
| `llm_test_result` | `{ok, message, models?}` | 「测试连接」结果：ok=false 时 message 说明原因（连不上/401/404…）；成功且网关支持 `/v1/models` 时附可用模型列表（供下拉） |
| `error` | `{code, message, fatal?}` | 错误；`fatal=true` 表示连接将关闭 |
| `pong` | `{}` | 心跳应答 |

**情绪取值约定**（v1 固定集合，前端做映射，后端不感知模型资源）：
`neutral / happy / sad / angry / surprised / shy / thinking / sleepy`

### 3.4 启动握手与鉴权（进程级）

```text
1. Electron 主进程启动时生成随机 token（32字节），准备随机空闲端口（或端口=0 由系统分配）
2. spawn Python：环境变量传入 PET_TOKEN、PET_DATA_DIR（用户数据目录）、PET_MODE
3. Python 启动完成（uvicorn 就绪）后，向 stdout 输出单行：
   PET_READY {"port": 51234, "pid": 12345}
4. Electron 解析该行 → 得到端口 → 通过 IPC 下发给渲染进程
5. 渲染进程连接 ws://127.0.0.1:51234 → 发送 hello（带 token）
6. 后端校验 token；失败：回 error(fatal) 并断开
```

**安全要点**：仅绑定 `127.0.0.1`；token 每次启动随机；防止本机其他程序窃用用户 API key。生产模式禁用 uvicorn 的 access log 中敏感字段。

### 3.5 二进制帧格式（Phase 2 预留，v1 冻结）

```text
[4字节 大端 JSON头长度 N][JSON头 N字节][音频数据]
JSON 头：{"type":"audio","message_id":"...","seq":0,"format":"mp3","sample_rate":24000,"final":false}
```

音频**不走 base64**（对比：Open-LLM-VTuber 用 base64 内嵌 JSON，体积膨胀 33%；我们直接二进制帧）。

### 3.6 连接保障

- **心跳**：前端每 30s 发 `ping`，10s 无 `pong` 判定断线。
- **重连**：指数退避（1s → 2s → 4s → … → 30s 封顶）；重连成功后自动 `load_history` 回填。
- **后端崩溃**：主进程检测子进程退出 → 按策略重启（5s 内最多 3 次，超限弹窗提示）→ 重启后 IPC 通知渲染进程重连。

### 4.1 llm 模块（BYOK 核心）

```python
# modules/llm/provider.py —— 抽象接口
class LLMProvider(Protocol):
    async def stream_chat(self, messages: list[Message], **opts) -> AsyncIterator[Chunk]: ...
    async def embed(self, texts: list[str]) -> list[list[float]]: ...
    async def test(self) -> tuple[bool, str]: ...   # 设置面板"测试连接"
```

- **实现**：`openai_compat.py` 基于 `openai` SDK 指向任意 `base_url` —— DeepSeek、智谱、通义、Moonshot、OpenAI、以及任何 OpenAI 兼容端点全部覆盖。
- **presets.py**：常用服务商预设（base_url、推荐模型名、是否支持 embedding），设置面板下拉即用。
- **embedding 策略**：默认**复用对话服务商的 embedding 接口**（同 base_url + key）；若该服务商不提供（如 DeepSeek 目前无 embedding API），设置里允许单独配置 embedding 服务商；再不行则**自动降级**：长期记忆停用并明确提示用户（不影响对话主功能）。
- 超时、重试、错误码翻译（限流/余额不足/网络）统一在此层处理，对上层只暴露业务化错误。

**系统提示词结构**（`prompts/`）：

```text
[人格设定]（名字、性格、说话风格，可在设置中编辑）
[情绪指令] 回复中用 <emo:xxx> 切换情绪，可用值：……
[记忆注入]（由 chat/context.py 动态拼接：用户画像 + 相关长期记忆）
```

### 4.2 chat 模块

- `history.py`：会话与消息的 SQLite 读写。消息表与 `sessions` 关联；支持按会话 id 拉取最近 N 轮。
- `context.py`：组装每次请求的 messages：
  `system(人格+情绪指令) → system(画像+记忆召回) → 最近 N 轮原文 → 本轮用户输入`。
  超长时从最旧轮次开始截断（保留 system）。
- `emotion.py`：**流式情绪标签解析器**。LLM 文本流中 `<emo:happy>` 标签随时出现：
  - 累积缓冲、按标签边界切分（避免半个标签发给前端）；
  - 标签剥离，转成 `emotion` 事件推送；
  - 流结束时若有残留半标签，作为普通文本吐出。
  - **宽容剥离（2026-10-16 实报修复）**：模型偶发写成 HTML 风格（`</emo>` / `<emo>` / `<emo/>`，
    漏了冒号与情绪名）——这类变体**就地剥离、不产生情绪事件**（否则标签字面原样漏给用户，
    实报"……还是随便聊聊？</emo>我随时待命……"）；流式前缀判定同步扩展（半个变体标签跨分片
    时等补齐，不提前当文本吐出）。提示词 `emotion_directive.md` 同步加了"禁止 HTML 风格"条款。
    剥离后的干净文本即落库源（`_emit` 的 clean_parts）——下发与落库一条修复全覆盖。

### 4.3 memory 模块

**职责**：让宠物"记得"用户。分三层：

| 层 | 载体 | 说明 |
|---|---|---|
| 短期 | messages 表 | 最近 N 轮原文直接进上下文 |
| 长期 | memories 表 + sqlite-vec | 事实/偏好/事件，向量检索 top-k 注入 |
| 画像 | profile 表（KV） | 姓名、称呼、喜好、忌口等结构化信息 |

- **写入时机**：会话结束（空闲 5 分钟）后触发后台提取任务；每轮不做（省 token、省 embedding 调用）。
- **提取**：用对话模型 + 专用提示词（`prompts/memory_extract.md`），输出 JSON 列表（`[{text, kind, importance}]`）；去重（与已有记忆相似度 > 阈值则合并/跳过）。
- **检索**：本轮用户消息 embed → sqlite-vec KNN top-k（默认 5）→ 按 importance 与时间衰减排序 → 注入上下文。
- **可观测**：设置面板提供"记忆管理"页（查看/删除记忆条目）——产品信任度关键。
- **实现状态（P3 ✅）**：结构化记忆 + 规则召回已落地（≤50 条全量注入；超阈值按 关键词×importance×时间衰减 取 top-8）；`memories_vec` 表待 embedding 源（网关暂无渠道）后按预留接口切换向量实现；画像/提取/去重/重启恢复均已验证。

### 4.4 voice 模块（P2 已实现 ✅）

```python
class TTSProvider(Protocol):
    async def synthesize(self, text: str) -> bytes: ...   # 整句 mp3
```

- **v1 实现：Edge TTS**（免费、用户零配置、默认 `zh-CN-XiaoxiaoNeural`）。
- **分句器**（`splitter.py`）：强边界（。！？；… .!?; 换行）遇即切、弱边界防过碎（≥6 字才切）、小数点保护、收尾符跨片段 lookahead——LLM 流式文本边生成边出声。
- **流水线（一句一帧）**：`sentence` 事件 → TTS 合成整句 → `audio` 二进制帧（`[4字节大端头长][JSON头][mp3]`，seq/final）→ 前端排队播放 + Web Audio 音量包络驱动口型。
- **reply_end 时序**：推迟到本轮音频帧全部送出之后（契约："音频永不超过 reply_end"）。
- **打断**：`interrupt` → cancel LLM 流 + 清空 TTS 队列（已合成未发的帧不再发）→ `reply_end{interrupted}`。
- **失败降级**：单句失败跳过继续；连续 ≥3 次禁用本次连接语音（error 码 `TTS_FAILED`，非致命）——文字对话不受影响。
- 风险登记：Edge TTS 为非官方接口、偶发单句失败（建议 provider 层加重试）；provider 抽象保证可平替（OpenAI TTS / 本地模型）。

### 4.5 behavior 模块：自主行为引擎（Phase 3，"生命感"核心）

> 桌宠的"生命感"= 无人管时它自己在活动。这来自行为引擎（纯工程能力），不来自 AI。
> 核心设计：**后端决策、前端执行**——后端是"什么时候做什么"的大脑，前端是"怎么动"的身体。

#### 4.5.1 分层原则（重要）

| 层 | 归属 | 例子 | 通信开销 |
|---|---|---|---|
| 微行为 | 渲染进程本地自驱 | 眨眼、呼吸、视线跟随鼠标、随机微表情 | 不经后端（Live2D 天然能力 + 渲染层逻辑） |
| 宏行为 | 后端决策 → 前端执行 | 走动、睡觉、张望、打盹、走到屏幕边缘 | WS 指令级：每几秒一条 |

**为什么不是位置流**：后端只下发意图（"向右走 300px"），前端在本地做移动动画（IPC → 主进程逐帧 `setBounds` + 缓动）与动作同步，完成或被中断后回报 `behavior_done`。WS 上无实时数据压力，走动流畅度只取决于本地实现。

#### 4.5.2 引擎主循环（engine.py）

```text
空闲计时器到期（随机 10–40s）
  → 掷骰：基础权重表 × 情境调制 → 选定行为
  → 下发 behavior 指令 → 等待 behavior_done
  → 记录消耗/冷却 → 进入下一轮
```

- **权重表**（behaviors.py）：`walk / look_around / daydream / nap / sleep / …`，每条含基础权重、时长范围、前置条件（如 sleep 仅深夜或低精力时可选）、目标动作（经情绪映射层映射到模型资源）。
- **情境调制**（rules.py）：
  - 时间段：白天活泼、深夜安静；
  - 软状态（见 4.5.3）：mood/energy 调制权重；
  - 对话进行中（thinking/speaking）：引擎静默，不抢戏；
  - **免打扰**：用户配置的免打扰时段 + 安静模式 → 只保留微行为。
- **不打扰原则**：行为永不抢占用户交互——任何 tap / drag / 对话开始，立即中断当前行为。

#### 4.5.3 软状态（mood.py）

| 状态 | 范围 | 变化来源 | 作用 |
|---|---|---|---|
| mood | 0–1 | 被摸/被聊 ↑，久无互动缓降 | 调制行为权重（活泼 ↔ 蔫）；同时注入 system prompt（"你现在心情…"），让说话方式和状态一致 |
| energy | 0–1 | 白天活动消耗，夜间/打盹恢复 | 低 → 更倾向睡眠类行为 |

**有意不做**：饥饿/清洁等数值衰减与惩罚机制——那是养成游戏，不是桌宠（新版 QQ 宠物也取消了生病死亡机制）。软状态只改变"它今天什么样"，不给用户增加负担。

#### 4.5.4 主动对话（proactive.py）

主动对话与宏行为分开调度但共用同一引擎（避免两套计时器互相打架），走完整 chat 流水线生成内容，推 `proactive` 事件。

- 触发：定时问候、整点、久坐提醒、mood 触发（"你很久没理我了"）。
- 频控：最小间隔 + 免打扰时段；**触发频率低于普通用户预期**（宁可少，不可烦）。
- 与宏行为的区别：宏行为无 LLM 参与（纯指令），主动对话有。
- **提醒先行（2026-10-18）**：到点提醒不调用 LLM——文案在创建时定稿并落库，
  由 `application/reminder_service.py` 定时推 `proactive{kind:"reminder"}`；
  proactive.py 的"问候/情绪触发"仍属后续阶段，两者共用同一 `proactive` 事件通道。

#### 4.5.5 前端执行器（behavior/executor.ts）

- 收到 `behavior` 指令 → 窗口移动（IPC → 主进程逐帧 `setBounds` + 缓动曲线）与 Live2D 动作同步播放，时长结束或被中断后回报 `behavior_done`。
- 被用户交互打断 → 立即停止移动与动作 → 回报 `behavior_done {interrupted: true}`。
- **环境上报**：连接时及窗口/屏幕变化时发 `env_update`（工作区、窗口位置、尺寸）——引擎据此决策（如"走到左边缘"需知道当前在哪、边界在哪）。

### 4.6 character 模块（角色系统）

**目标**：宠物形象/人格可自定义——企鹅、猫、兔子……以及名字、性格、声音（Phase 2）。

**角色包**（存放在用户数据目录 `characters/<id>/`，用户可增删）：

```text
characters/xiaodou/
├── manifest.json      ← 元数据：显示名 / 物种 / 性别 / 性格标签 / 简介 / TTS 声音偏好
├── persona.md         ← 人格设定：性格、语气、称呼方式（作为 system prompt 的人格部分）
├── emotion_map.json   ← 情绪 → 表情/动作映射（模型适配层的数据，见 §5.3）
└── model/             ← Live2D 模型资源（.model3.json + 贴图 + 动作/表情文件）
```

**自定义维度**：

| 维度 | 实现方式 |
|---|---|
| 形象/物种 | 换角色包 = 换 Live2D 模型；情绪映射层保证其余代码零改动 |
| 名字 | manifest 字段，用户可改 |
| 人格 | `persona.md` 提示词；**性别只是其中一个可选字段，性格标签（活泼/温柔/傲娇/高冷/黏人…）可自由组合**——对体验影响最大 |
| 声音（Phase 2） | manifest 中 TTS voice 偏好，设置面板可覆盖 |

**注册表**：模块启动时扫描 `characters/`，用 Pydantic 校验 manifest；坏角色包跳过并记日志（不阻断启动）；提供 list / get / current 查询。

**persona 注入**：`application/chat_pipeline` 组装上下文时从当前角色的 `persona.md` 读取并注入 system prompt（chat 模块不直接依赖 character 模块，由 application 以参数传入）。

**切换流程**：`switch_character` → 校验存在 → 更新配置 → 回 `character_changed` → 前端卸载旧模型、加载新模型 →（可选）新角色用新人格自我介绍一句。

**内置角色**：随安装包附带 1–2 个免费授权模型作为初始角色，首启复制到用户目录（此后用户可自由替换/新增）。

### 4.7 tools 模块：内置工具机制（2026-10-16 决策）

**目标**：让模型知道并调用"真实动作"（不只是嘴上说）——首个工具 `open_settings`（打开设置
面板），解决"用户说'打开设置'、模型却列快捷键甚至陪你喊"的体验问题；后续知识库查询等工具
以"注册一条"的成本接入。

**架构决策（与用户评审定稿）**：**不引入 LangChain/LangGraph**——模型接入维持"仅 OpenAI
兼容协议"战略（国内主流云厂商 + 本地部署全覆盖；不兼容协议【Claude/Gemini 原生】留
`LLMProvider` 接口按需单点适配，不锁死）；工具机制自研轻量（协议层即 OpenAI `tools` 字段 +
流式 `tool_calls` 解析），零新框架依赖、与现有自研管道（emo 标签/分句/记忆注入）无缝共存。

**三层保底**（`application/chat_pipeline` 实现；注入 `tools` 注册表后启用，缺省 None = 旧行为）：

1. **快通道（内置指令词表）**：`match_directive` 命中词表（"打开设置/设置面板"——迁移自
   前端关键词，见 §7.6.1）→ **不调 LLM**：本地 ack 走正常事件流（token → 分句/TTS → 落库，
   情绪 happy），`reply_end` 后派发 `tool_call`。高频指令**必达**，不受模型/网关不确定性影响。
2. **模型路径（tools 协议）**：请求携带 `tools`（registry → OpenAI 格式）→ 流式累积
   `Chunk.tool_delta`（按 index 归组拼 arguments）→ `reply_end` 之后派发 `tool_call`。
   模型只调工具、没产出正文时（真机实测会发生）用该工具 `ack` 补一句话（走 token/分句，
   TTS 可播报），避免用户端静默。
3. **降级链**：带 tools 的请求被 `LLM_BAD_REQUEST` 拒绝且本轮无任何产出（疑似网关/模型不支持
   tools）→ 摘除 tools 重放一次；再败以**第一次**错误收尾。降级置**进程级标记**，后续轮不再
   携带 tools（快通道照常）；`prompts/capabilities.md`（能力清单，每轮热读）兜底引导——模型
   知道有此能力，会引导用户说"打开设置"，而非编造快捷键。
4. **强制工具（2026-10-18 真机缺陷后补）**：模型对“1 分钟后提醒我睡觉”这类请求会随机只回
   “好，提醒你”而不真正调用 `create_reminder`，导致用户以为设上了、到点无提醒。对“提醒动作 +
   具体钟点/时长”的高置信度意图，`match_forced_tool` 返回 `create_reminder`，请求携带
   `tool_choice` 强制模型调用；网关拒绝 `tool_choice` 时先摘它保留 tools 重试，仍拒绝再走
   摘 tools 降级；若最终仍未返回该调用，回复后推 `reminder_tool_missed` 警示 notice，绝不静默
   假成功。只有“明天/晚上/每天”这类模糊日期不强制，保留模型反问“几点”的空间。

**工具定义与执行位置**（`backend/modules/tools/`）：

| 概念 | 说明 |
|---|---|
| `ToolSpec` | `name / description / parameters(JSON Schema) / executor / handler / ack`（ack = 模型没说话时的确认话兜底文案）；2026-10-18 增 `prepare`（frontend 型派发前的名字→精确值解析/用户原话校验）、`needs_user_text`（backend handler 额外拿用户本轮原话）、`feedback`（backend 结果回喂模型并触发续写轮，联网搜索用） |
| `ToolRegistry` | 注册（重名报错，早暴露装配错误）/ 查询 / `to_openai_tools()` 转协议格式；由 Runtime 装配（进程内只读） |
| `executor="frontend"` | 后端只声明"调什么"，`tool_call` 事件下发前端执行（`modules/tools` 执行器表按 name 分派；如 open_settings → `settings.open()`）；未知 name 静默忽略（前后端版本漂移降级） |
| `executor="backend"` | 后端在 `reply_end` 前直接执行 `handler(args)`，结果以确定性 `notice` 推送（2026-10-18 起用于提醒工具 create/list/cancel）；"结果回传续写"（tool 结果回填再生成）仍属后续扩展 |

**边界与约束**：llm 域不 import tools 域（只收 `list[dict]`）；工具调用不进对话历史
（assistant 只存正文/补话）；快通道仅 frontend 型工具（backend 型需要模型参数，命中词表也走
正常流）；`tool_call.id` 为将来"结果回传配对"预留（当前前端按 name 执行、无回执）。

**实测锚点（2026-10-16，deepseek-flash + 内网网关，真机）**：stream+tools 透传正常；模型行为
三类均覆盖——快通道（88ms 全流程）、只调工具没正文（2s tool_call → ack 补话，emotion=neutral
可与快通道 happy 区分）、有正文+调工具（reply_end 后派发顺序正确）；能力清单含"只按**本轮**
用户意图判断"条款（防上下文带偏重复调用，实测生效）。

### 4.8 memory_book 模块：记忆本（2026-10-18）

**定位**：用户明确说"记住/收藏"的**精确条目**（网页链接 / 本机文件或文件夹 / 短文本），
名字是主键，值原样保存；打开时模型只传名字，后端取精确值。与长期记忆（§4.3）分工：

- 长期记忆 = 关于用户的模糊事实/偏好，自然语言召回，会被模型改写/截断；
- 记忆本 = 精确值（URL/路径），不允许改写——一个字符错就打不开，不能塞进自然语言记忆。

**领域文件**（`backend/modules/memory_book/`）：

| 文件 | 职责 |
|---|---|
| `store.py` | `saved_items` 读写；值校验（http/https、绝对路径必须存在、文本 1–500 字）；自动起名（域名/末级目录名/前 12 字，重名加 `-2`）；同名 upsert；遗忘名单读写 |
| `paths.py` | 路径归一化（展开 `~`/环境变量、realpath 解析软链接）+ 受保护目录判定（根/主目录/系统目录/应用目录/祖先），**只判定不删除** |
| `format.py` | system 注入块：只放名字 + 类型（文本类附值）；**链接 URL 与本机路径不注入模型上下文** |

**工具**（`modules/tools/builtin.py`，`build_default_registry(reminders, memory_book)` 注入后注册）：

| 工具 | 执行方 | 说明 |
|---|---|---|
| `save_item` | backend | 批量保存/同名更新（最多 10 条）；仅链接/路径/编号等**精确条目**（或用户明确“存到记忆本”）时由模型自行调用；偏好/事实交给长期记忆（2026-10-19 取消强制路由） |
| `list_items` | backend | 列表 + 路径存在性检查；用户问具体地址/内容时用 |
| `rename_item` | backend | 改名；冲突返回可展示原因 |
| `delete_item` | backend | **只删记录、不动磁盘文件**；用户本轮必须点名；路径条目只说"删掉"时返回反问（删记录还是删文件） |
| `open_item` | frontend + `prepare` | 名字 → 精确值；临时 URL 必须是用户本轮消息里的（防文件/网页内容诱导）；文本条目不可打开；路径失效给更新/删除提示 |
| `delete_path` | frontend + `prepare` | 删除真实文件/文件夹；后端先判存在/受保护/歧义；前端弹**确认气泡**；主进程再判一次后 `shell.trashItem` |
| `run_program` | frontend + `prepare` | 启动本机程序（只启动本体、不带参数）；后端按记忆本 / 用户点名的应用名 / 临时绝对路径解析；前端交主进程 launcher 域执行；临时路径弹**确认气泡**，记忆本与已安装应用免确认 |

**删除真实文件的安全链**（用户定稿：不能偷偷删）：

1. 后端 `prepare_delete_path`：只校验并返回目标，**不删除**；路径条目必须说清"删文件"，
   只说"删掉 X"返回"只删记录还是连文件一起删"的反问；
2. 前端执行器 → 主进程 `SYSTEM_DELETE_PATH_CONFIRM`：气泡显示**精确绝对路径** +
   「删除 / 取消」；取消/点别处/120s 超时什么都不做；
3. 主进程二次校验（`electron/system/path-safety.ts`）：根/主目录/系统目录/应用目录/
   AppData 拒绝；目标是受保护目录的祖先也拒绝；打开文件还拦截可执行/脚本扩展名；
4. 执行 `shell.trashItem`（系统回收站/废纸篓，**可恢复**），不做永久删除、不拼 shell 命令。

**遗忘联动**：

- 删除记录时把值写入 `forgotten_values`（30 天过期）并删除长期记忆中含同值的条目；
- 后台记忆提取经注入的 `is_forgotten` 过滤，命中跳过——防止从旧对话把用户已删掉的
  链接/路径重新捞回来；
- 重新保存同一个值会清除遗忘名单；
- 更新条目值时，旧值同样清理并进入遗忘名单。

**运行程序的安全链**（2026-10-19）：

1. 记忆本新增 `program` 类型，**只能由设置页**（WS `client_role=settings`）创建；
   对话工具 `save_item` 的 enum 不含 program，服务层再拦一次——防模型被网页/文件内容
   诱导后批量登记"免确认可运行"的程序；
2. 后端 `prepare_run_program` 解析三种来源：记忆本条目（免确认）、用户本轮点名的
   已安装应用名（免确认）、用户本轮明确给出的绝对路径（确认）；系统应用名/临时路径
   **必须出现在本轮原话**；
3. 前端只传输；主进程 launcher 域（`electron/launcher/`）是唯一执行边界：
   - `mode:'name'` 只允许主进程自己扫描到的 `.desktop`，渲染进程不能传路径；
   - `mode:'path'` 独立校验绝对路径/普通文件/执行位（POSIX）或 `.exe|.com`（Windows），
     拒绝 `.desktop`、shell 本体、`/proc|/sys|/dev`；未标记 trusted 时弹确认气泡；
   - 永远 `shell:false`、参数数组；`.desktop` 的字段码剥离但保留自带参数；
   - detached 启动，宠物不跟踪、不 kill 子进程；每 sender 10 次/分钟限流。

**边界（v1 不做）**：永久删除、任意命令/shell 字符串/管道/重定向、带用户参数启动、
终端应用启动、后台文件监听/全盘搜索、链接联网预检
（打开交给浏览器；以后可加"体检"工具做 HEAD 检查）、多条路径一次性批量确认（一条一个确认）。

### 4.9 search 模块：联网搜索（2026-10-18）

**目标**：让宠物能查实时网页、读网页正文，并带着来源回答；复用用户已有的 DeepSeek
Key，不引第三方搜索服务。

**官方接口**（`https://api.deepseek.com`，与对话 API 同一 Bearer Key）：

| API | Endpoint | 要点 |
|---|---|---|
| Search | `POST /v1/tools/search` | `query` 1–128 字（支持 `site:`/`-site:`/`"精确短语"`/`lang:`/`after:`/`before:`）、`count` 1–50（默认 10，不影响价格）、`ori_question`、`need_content`；返回 `results[]`（title/url/snippet/summary/content/date/authority/rerank_score） |
| Fetch | `POST /v1/tools/fetch` | `url` ≤8192、http/https、无用户名密码；返回 `{title, content(Markdown)}` |

**计费/限流**：Search、Fetch 各 ¥5 / 1000 次**成功**请求；只有 HTTP 200 且结果/正文非空
计费；失败/无结果/超时不计费；北京时间 **2026-11-01 00:00** 起计费；每个账号两个端点
各 **5 QPS**（超限 429）。配置默认 `[search].enabled=true`（默认开启），用户可在设置 → 搜索里关闭。

**架构**：

- `modules/search/provider.py`：`SearchProvider` 抽象 + `SearchResult/SearchOutcome/FetchOutcome`；
- `modules/search/deepseek.py`：HTTP 实现（超时、5 QPS 间隔、408/429/5xx 重试一次、错误翻译）；
- `modules/search/format.py`：结果 → `model_content`（编号来源 + 引用要求 + **网页内容不可信**提示）；
- `application/search_service.py`：开关检查 + 调 provider + 生成"通知 message"与"模型资料 model_content"；
- `modules/tools/builtin.py`：注册 `web_search` / `web_fetch`（backend 型 + `feedback=True`）；
- `application/chat_pipeline.py`：**唯一的第二轮路径**——
  1. 第一轮模型调用 `web_search`/`web_fetch`；backend handler 返回 `model_content`；
  2. 流水线追加 assistant `tool_calls` + 对应 `tool` 消息，**不携带 tools** 再调一次 LLM；
  3. 第二轮文本续写进同一条回复，最后统一 `reply_end`；搜索通知在 `reply_end` 之后推送。
- `llm/provider.py` 的 `ChatMessage` 增加 `tool_calls` / `tool_call_id`；OpenAI 兼容层原样
  序列化 tool 消息。普通对话消息不带这两个字段，行为与旧版一致。

**安全与成本**：

- 开关默认开启、可随时关闭；只有模型判断需要实时信息或用户明确说"搜一下/查一下"才调用；
- 搜索词不塞入用户隐私/本机路径/文件正文；
- 网页内容按不可信资料处理：只引用，不执行网页里的指令；
- `count` 默认 5、`need_content=false`（用 600–800 字 summary）；Fetch 正文按
  `max_fetch_chars`（默认 6000）截断；
- 5 QPS 限速；失败提示区分 401（Key 无效）/402（余额不足）/429（太频繁）等。

**边界（v1 不做）**：搜索结果前端卡片/来源面板、自动抓取所有结果页、搜索历史、流式搜索
（当前一次工具调用拿完结果）。

## 5. 前端模块设计

### 5.1 主进程：窗口域（平台适配层）

统一接口（渲染进程只见 IPC，不见实现）：

```ts
interface WindowCapability {
  setClickThrough(on: boolean): void;        // 点击穿透开关
  isClickThrough(): boolean;
  setAlwaysOnTop(on: boolean): void;
  isAlwaysOnTop(): boolean;
  startDrag(cursor: Point): void;            // 拖拽（透明窗口下自绘，不用 -webkit-app-region）
  dragMove(cursor: Point): void;
  endDrag(): void;
  setScale(scale: number): void;             // 宠物缩放
  getWorkArea(): Rect;                       // 工作区（防拖出屏幕）
  setInteractiveRects(rects: Rect[]): void;  // 渲染侧上报可交互矩形（X11 形状穿透依据）
}
```

- **实现注册表**：`registry.ts` 按 `process.platform` 选择实现；**禁止 `if (isWindows) else` 式二分假设**——新增平台 = 新增一个实现文件 + 注册一行，调用方零改动（macOS 远期扩展就靠这条约定）。
- `win32.ts` / `linux.ts` 分别实现；`linux.ts` 内部再检测会话类型：
  - **X11**（已在 Deepin 实测，见 `docs/报告/前端/verify-report.md`）：`transparent + frame:false + alwaysOnTop` 全能力可用；**穿透用窗口形状 `setShape`**——实测 `setIgnoreMouseEvents({forward:true})` 在 X11 下不转发 mousemove，悬停检测无法闭环（Windows 不受此限）。
  - **Wayland**：透明与穿透可能受限 → 降级策略：引导以 XWayland 运行（`--ozone-platform=x11`），或降为不透明窗口并在首启说明。
- **macOS（远期预留，本期不写实现）**：Electron 在 macOS 上透明/置顶/穿透均有原生能力，接口无缺口；落地时注意三点：① `alwaysOnTop` 的 level 语义（floating 层级）；② 全屏 Space 上的显示行为；③ 分发必须 Apple 开发者账号签名 + 公证（见 §8.2）。`darwin.ts` 未实现期间 registry 返回降级实现（不透明窗口、无穿透），保证未来在 macOS 上至少能先跑起来。
- **点击穿透交互模型**（关键，含实测修正）：目标不变——"形状外放行给桌面、悬停时接管"。X11 实现：`setShape` 把输入区收缩为宠物 hitbox（形状外系统级放行），渲染侧 hover 逻辑作为动态层；Windows 用 `setIgnoreMouseEvents(true,{forward:true})` + 渲染悬停检测（该组合 X11 实测不工作，平台差异收敛在实现文件内）。
- **拖拽**（含实测修正）：渲染侧 `pointerdown`（pointer capture）→ `pointermove` 上报屏幕坐标（rAF 节流）→ 主进程 `setBounds` 跟随 → `pointerup` 对齐落点；**禁止**用 `screen.getCursorScreenPoint()` 轮询（X11 下是事件驱动缓存，光标出窗即冻结）。
- **空气让路 · 像素级命中（2026-10-16 增补，终版交互）**：解决"兔子矩形四角/两侧透明空气吃点击"（用户实反馈：想点宠物旁边的文件点不到——矩形 hitbox 内非模型像素也吃鼠标）。机制：
  - **渲染侧判定**：`PetRenderer` 新增可选 `hitTest(x,y): boolean`——先 DOM 层（`elementFromPoint`：面板/输入等交互元素=实体；纯装饰如气泡 `pointer-events:none` 自然穿透）；否则 Three.js `Raycaster` 对模型网格求交（命中=实体）；**拖拽中恒 true**（锁定接管）。渲染器未实现该接口 → 渲染侧恒报"实体"=现状行为（fallback 零分支）。
  - **主进程输入接管状态机**（TAKEN 接管 / YIELDED 让路，统一收编旧渲染悬停逻辑）：
    - **TAKEN**：光标 mousemove（实时）驱动渲染 hitTest；渲染报"空气"→ `setIgnoreMouseEvents(true, {forward:false})` → YIELDED（**显示不受影响**——X11 走 ShapeInput 路径，与旧 `setShape`（显示+输入绑死）机制刻意不同）；状态**只由渲染报告驱动**（不设主进程几何自判——曾试"几何守卫"与渲染去重失同步导致卡死，已移除）。
    - **YIELDED**：穿透态收不到窗口事件 → 主进程经**光标源**查询（**Linux=xdotool `getmouselocation`（XQueryPointer 请求-应答，~50ms；实测零丢击 120/120）**；⚠️ XI2 事件流（`xinput test-xi2`）**不可用**——指针事件按"指针下窗口"投递且首个选择者截获，桌面场景必有窗口，root 观察者收不到）→ 光标回窗内 → 经 `pet:pointer-pos` 推坐标（切 YIELDED 时补推一次 null 作去重信号）→ 渲染 hitTest 回报"实体" → `setIgnoreMouseEvents(false)` 恢复接管；光标在窗外 → 保持让路。
    - **降级链**：xdotool 缺失/连续失败 → screen 轮询 + 脉冲刷新（短切 setIgnoreMouseEvents 刷新 X11 事件驱动缓存；**代价 ~10% 丢击**，仅降级路径）。
    - **防抖**：渲染侧"变化才上报"语义下，主进程以"连续 2 次一致（提前切）或单次报告 + 120ms 确认窗口"实现（边缘毛刺不抖）。
  - **契约**：`pet:report-hit-test {solid}`（渲染→主）；`pet:pointer-pos {x,y}|null`（主→渲染，让路态推送，null=出窗/状态去重信号）。
  - **实测结论（2026-10-16，开工风险点均有实证）**：① `setIgnoreMouseEvents` 只切输入不切显示 ✓（像素级截屏对比）；② 穿透态 `getCursorScreenPoint` 为事件驱动缓存、**冻结不可用**（→ xdotool 查询源）；③ 快速切换稳定 ✓；集成冒烟：滑入接管 166~225ms / 让路 121~125ms / 空气点击穿透 120/120。

### 5.2 主进程：Python 子进程域

- 开发态：spawn `python -m backend.main`；生产态：spawn `resources/backend/backend(.exe)`（PyInstaller onedir）。
- 解析 stdout 的 `PET_READY` 行 → IPC 广播给渲染进程。
- 存活监控：`exit` 事件 → 指数退避重启（最多 3 次）→ 超限托盘通知。
- 退出清理：`before-quit` 时先发优雅退出信号（WS 无关，走进程信号），3s 未退则 kill；Windows 注意子进程树清理。

### 5.3 渲染进程：pet 域（可插拔渲染器）

**架构**：`PetRenderer` 接口 + 工厂（`createPetRenderer(kind)`）——渲染实现可插拔，换实现不改调用方。

- **当前实现：部件动画渲染器**（`renderers/part-animation/`）：程序化 SVG 分层绘制 + rAF 驱动；造型参数、情绪→部件姿态映射、动画常量三者分离（config / emotion-map / animator），便于调整与复用其他形象。**零外部依赖、素材版权自有**（产品化绕开 Live2D 授权问题）。
- **Live2D 为未来实现位**：同一接口的另一实现（PixiJS + pixi-live2d-display 活跃 fork，见 §11），工厂内保留分支；接入时情绪映射数据同样按角色包规范存放（见 §4.6）。
- **渲染循环独立于 React**：rAF 自驱，React 只负责挂载/卸载与状态订阅，杜绝重渲染影响动画帧率。
- **口型**：`setMouth(level 0-1)` 接口已留；P2 由 TTS 音频驱动（部件动画 = 嘴形切换，Live2D = ParamMouthOpenY）。
- **交互手势**：单击（摸头）→ 本地即时反应 `playReaction`；上报后端（pet_event）在后端实现该事件后开启（前端开关已留）。
- **性能**：无交互且无对话时降帧；窗口隐藏时暂停循环。
- **第三个实现（P3）：GLB 外部模型**（`renderers/glb-model/`）：加载 AI 生成/外部制作的 glTF/GLB（当前为混元 3D 生成的兔子，50k 面、贴图压缩至 1.7MB、真机成本低于程序化版）；无骨骼模型用**整体姿态层**（8 情绪/6 状态/移动速度感知）；**骨骼版接入点已预留**（AnimationMixer + 窗口测速挂钩、setMouth 驱动下颌/形态键）。
- **睡姿子模块**（`renderers/glb-model/sleep/`，2026-10-19）：两个独立趴睡静态 GLB（浅睡=无口水 / 深睡=有口水，23MB 原文件各经纹理压缩至 1.3MB）。每次进入 sleeping 按 50% 随机选一个模型，**睡眠期间不切换**；选到深睡模型时口水初始隐藏，满 **10 秒**用 shader alpha 淡入（表示睡得深）。无骨骼/无 morph，腹部起伏用顶点着色器按世界 Y 范围沿法线隆起；口水摆动用局部顶点窗口，口水主体用 baseColor 浅蓝色识别（几何窗口只覆盖尖端）。Zzz 用 DOM/CSS 覆盖层（白色描边、错峰上浮）。浅睡未就绪时直接用深睡，两个都失败则回退站姿程序化睡觉，站姿模型与表情/耳朵层不受影响。**画布容器 `.pet-canvas-mount` 208→240px**：浅睡模型左耳投影到画布 x=-2.6px 会被 WebGL 画布边缘裁掉（深睡刚好 0.38px 未越界），加宽只增加左右可见范围，不改变视觉大小与中心。

### 5.7 气泡系统（bubble 域：主进程编排 + 独立渲染窗）

  主进程 setBounds（首帧预估定位、宁大勿小，上报后收紧）；防出屏摆放为纯函数
  （`electron/bubble/geometry.ts`：优先后上 tail=down、贴边翻向、横向夹进工作区；尾尖对齐常量
  与渲染侧 bubble.css 三方约定）。
- **交互两态**：
  - 菜单态（可聚焦、blur 收起——像原生右键菜单）：右键宠物菜单、清空确认；
  - 展示态（说话气泡）：showInactive 不聚焦，但**接鼠标**——Linux 用窗口形状

- **动画分工**（照 ball-animation 域先例：主进程是指挥、渲染页负责"画"）：`motion` 预设——`hand`（手来手回：

- **动作分发**（气泡窗 → ACTION → 主进程按当前内容白名单校验执行）：菜单（开始/结束教学、打开
  设置、清空聊天、隐藏）、确认（清空 / 取消）、说话气泡（`expand` 打开工作模式 / `close` 收掉）；

- **渲染残缺修复**（2026-10-16，真机 KWin/Chromium 特有）：气泡窗在"窗口尺寸稳定后不再有内容变化"

  菜单与"让位恢复后的气泡"必残）。排查排除：invalidate 强制重绘、外部真实 resize、绘制属性抖动

  **只有 DOM 级重建能全局强制重绘**。修复三层：①每次弹出销毁重建窗；②每次唯一 partition

## 6. 数据模型与配置

### 6.1 存储位置（前后端强制一致）

由 Electron 主进程计算用户数据目录，经环境变量 `PET_DATA_DIR` 传给 Python：

| 平台 | 路径 |
|---|---|
| Windows | `%APPDATA%\AiDesktopPet\` |
| Linux | `~/.config/ai-desktop-pet/` |

目录内：`config.toml`、`pet.db`、`characters/`（角色包：模型 + 情绪映射 + 人格）、`logs/`。

### 6.2 SQLite 表结构（pet.db）

```sql
-- 会话
CREATE TABLE sessions (
  id          TEXT PRIMARY KEY,
  title       TEXT,
  created_at  INTEGER NOT NULL,
  ended_at    INTEGER
);

-- 消息历史
CREATE TABLE messages (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id  TEXT NOT NULL REFERENCES sessions(id),
  role        TEXT NOT NULL,            -- user / assistant
  content     TEXT NOT NULL,
  emotion     TEXT,                     -- 助手消息的情绪标签
  created_at  INTEGER NOT NULL
);
CREATE INDEX idx_messages_session ON messages(session_id, created_at);

-- 长期记忆（向量走 sqlite-vec 虚拟表）
CREATE TABLE memories (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  text        TEXT NOT NULL,
  kind        TEXT NOT NULL,            -- fact / preference / event
  importance  REAL DEFAULT 0.5,
  created_at  INTEGER NOT NULL,
  last_used_at INTEGER
);
CREATE VIRTUAL TABLE memories_vec USING vec0(
  memory_id INTEGER PRIMARY KEY,
  embedding FLOAT[1024]                 -- 维度随选用 embedding 模型，配置中声明
);

-- 用户画像
CREATE TABLE profile (
  key         TEXT PRIMARY KEY,
  value       TEXT NOT NULL,
  updated_at  INTEGER NOT NULL
);

-- 提醒（2026-10-18；本地 ISO 时间含偏移；重复规则白名单 none/daily/weekdays/weekly）
CREATE TABLE reminders (
  id          TEXT PRIMARY KEY,
  text        TEXT NOT NULL,
  due_at      TEXT NOT NULL,
  repeat_rule TEXT,
  status      TEXT NOT NULL DEFAULT 'scheduled',  -- scheduled / fired / cancelled
  created_at  TEXT NOT NULL,
  fired_at    TEXT,
  session_id  TEXT
);
CREATE INDEX idx_reminders_due ON reminders(status, due_at);

-- 提醒触发事件（每次到点一条；未读 = acknowledged_at IS NULL；2026-10-18 列表/已读）
CREATE TABLE reminder_events (
  id              TEXT PRIMARY KEY,
  reminder_id     TEXT NOT NULL,
  batch_id        TEXT NOT NULL,
  text            TEXT NOT NULL,
  due_at          TEXT NOT NULL,
  fired_at        TEXT NOT NULL,
  acknowledged_at TEXT,
  late            INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_reminder_events_unread ON reminder_events(acknowledged_at, fired_at);
CREATE INDEX idx_reminder_events_fired ON reminder_events(fired_at);

-- 记忆本（2026-10-18）：用户明确要求记住的链接 / 本机路径 / 短文本。
-- 名字是主键（name_key 归一化后唯一）；值原样保存，打开时按名字取精确值。
CREATE TABLE saved_items (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  name_key    TEXT NOT NULL,              -- 去空白 + casefold
  kind        TEXT NOT NULL,              -- link / path / text
  value       TEXT NOT NULL,
  is_dir      INTEGER NOT NULL DEFAULT 0, -- kind=path：文件夹/文件（展示用）
  created_at  INTEGER NOT NULL,
  updated_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_saved_items_name_key ON saved_items(name_key);
CREATE INDEX idx_saved_items_kind ON saved_items(kind);

-- 遗忘名单（2026-10-18）：删除记忆本条目的值（casefold），后台记忆提取据此
-- 跳过含该值的记忆；30 天过期，重新保存同一个值时清除。
CREATE TABLE forgotten_values (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  value_key   TEXT NOT NULL,
  created_at  INTEGER NOT NULL,
  expires_at  INTEGER NOT NULL
);
CREATE UNIQUE INDEX idx_forgotten_values_key ON forgotten_values(value_key);
```

## 7. 关键流程时序

### 7.1 一次文字对话（Phase 1 主链路）

```text
用户输入文字
  → 渲染进程 chat 域：气泡显示用户消息，发 user_message
  → 后端 interfaces/ws 鉴权/解析 → application/chat_pipeline
      1. chat/history 写入用户消息
      2. memory 检索：用户消息 embed → top-k 记忆 + 画像
      3. chat/context 组装 messages（system+画像+记忆+最近N轮）
      4. llm/stream_chat 发起流式请求
  → 流式回来：
      · chat/emotion 解析：发现 <emo:xxx> → 推 emotion 事件（前端切表情）
      · 文本增量 → 推 token 事件（前端逐字渲染）
      · 句子完成 → 推 sentence 事件（Phase 2 触发 TTS）
  → 流结束：推 reply_end（P2 起：等待本轮 TTS 音频帧全部送出后再推）
  → 前端：气泡定型；宠物状态 idle
  → （空闲 5 分钟后）后台：记忆提取任务 → 写 memories（embed + 去重）
```

### 7.2 打断（Phase 2 起常驻）

```text
用户说话 / 点"闭嘴"
  → 前端发 interrupt
  → 后端：cancel LLM 流任务 + 清空 TTS 队列
  → 推 reply_end { interrupted: true }
  → 前端：停止音频播放、清口型、气泡标注"已打断"
```

### 7.3 后端崩溃恢复

```text
Python 进程退出（崩溃）
  → 主进程检测 → 5s 内重启（≤3 次）
  → 新进程 PET_READY（新端口+新 token）→ IPC 下发
  → 渲染进程 WS 重连（指数退避）→ hello 鉴权 → load_history 回填
  → 托盘提示"大脑已重启"（仅异常时）
```

### 7.4 自主行为与中断（Phase 3）

```text
空闲计时到期（10–40s 随机）
  → behavior/engine 决策：权重表 × 情境调制 → 选定行为（如 walk）
  → 推 behavior {id, name:"walk", params:{direction:"right", distance:300}}
  → 前端 behavior/executor：窗口缓动移动 + 播行走动作（本地执行）
  → 完成 → behavior_done {id} → 引擎记录 energy 消耗 → 冷却 → 下一轮

期间用户摸头 / 开始说话：
  → 前端立即停止移动与动作 → behavior_done {id, interrupted:true}
  → 引擎：mood 提升（被摸）→ 进入交互优先状态（引擎静默一段时间）
```

### 7.5 教学模式（P5）——讲台与黑板

**定位**：把"AI 回复"变成"AI 讲课"。宠物成为讲师、黑板成为输出面——用于讲题、分析文件、教学等"需要大输出面"的场景。

#### 7.5.1 形态与交互

```text
┌────────────────────────────────┬──────────────────┐
│                                │                  │
│         （用户工作区）           │    黑   板        │
│                                │  ┌────────────┐  │
│  ┌──┐  ↑头顶问题气泡（最多 4 条） │  │ 问题 → 讲解  │  │
│  │🐰│                          │  │ 流式板书…    │  │
│  └──┘                          │  └────────────┘  │
│  讲台位（屏幕左下角）             │      [输入条]     │
└────────────────────────────────┴──────────────────┘
```

- **进入**（显式触发，第一版不做 LLM 自动识别）：托盘菜单"教学模式" / 右键宠物菜单"开始教学" / 聊天里说"开始教学""教学模式"（前端关键词匹配）。（说话气泡悬浮条「⤢ 展开」自 2026-10-19 起改为打开工作模式，不再进教学。）
- **进入编排**：黑板从右缘滑入（260ms）→ 宠物走回讲台位（复用 moveTo 缓动）→ 聊天面板自动收起（内容都在黑板上）→ 行为引擎暂停（后端 `set_mode`）→ 宠物进入待讲状态。
- **对话**：教学模式下输入在**黑板底部输入条**（转发给宠物窗口的 WS 链路发送）；输入条支持附件（**回形针在输入框内部最左侧** / 粘贴绝对路径 / 拖入，最多 3 个，正文由后端读取）——"讲课/讲文档"场景：带文件后让宠物分章节讲解。回复流式"板书"到黑板；宠物照常做表情/口型/语音（全部复用现有链路）。
- **讲课提示**：宠物面在教学模式中发送 `user_message` 时自动带 `options.teaching=true`，后端追加临时 system 提示（老师口吻、先大纲再逐章、重点用列表/表格/代码块），不落库、不进历史。
- **头顶问题气泡**：用户提过的每个问题成为一个气泡，在宠物头顶堆叠（最新贴近头顶、往上渐旧；**最多 4 条可见 + "+N"省略**，仅教学模式显示）。点击气泡 → 黑板滚动/跳转到该问题的讲解段落并闪烁高亮（"课堂目录"）。
- **拖动 = 让路**：教学模式下用户拖动宠物（判定为拖拽的那一刻）→ 黑板**卷起折叠**成右侧贴边小角标（24×140，可无视）；宠物停在被拖到的位置待机。语义：用户有要紧事，全部让位。
- **恢复三入口**（折叠 ≠ 下课，上下文/板面/滚动锚点全保留）：
  ① 点右侧小角标 → 黑板卷出（原位恢复、含上次滚动位置）；
  ② 点头顶某问题气泡 → 卷出并直接跳到该处；
  ③ 直接对宠物打字/说话 → 自动卷出（省一步）。
  恢复时：宠物（若被拖远）走回讲台位；黑板书"上次讲到这"的段落高亮（轻量衔接，不额外烧 LLM 请求；衔接话术为第二轮可选项）。
- **退出**（下课）：黑板右上 ×、聊天里说"结束教学/下课"。黑板滑出收起，宠物**回到开课前的位置**（与关闭设置窗同一条回位链路，2026-10-17 用户定稿），随后恢复正常（气泡消失、聊天面板恢复、行为引擎恢复、`set_mode: normal`）。

#### 7.5.2 窗口架构（新增 board 窗口域）

- **黑板窗口**（electron 主进程管理）：宠物**所在显示器**的右上区域；展开态宽 `min(工作区宽 55%, 1000px)`、高 `工作区高 - 120px`、右距 20px、垂直居中；圆角 20、深色半透明（`rgba(18,20,28,0.92)`）、置顶、无边框、skipTaskbar；折叠态 24×140 贴右缘。参数集中一处便于调。
- **渲染入口**：黑板开**独立入口 `board.html` + `src/board/`**（BoardApp）——与 `ball-animation.html`（魔法球窗）同模式（electron-vite 多页面 input 加一行）；复用同一 preload 基建。
- **数据流（镜像方案，单向主线）**：对话仍由**宠物窗口**发起（WS 主体不动）——宠物窗口收到 `user_message` 回声/`reply_start`/`token`/`reply_end` 后**镜像**给主进程 → 主进程路由给黑板渲染（黑板是"哑显示"，不自己连 WS）。输入反向走一次转发：黑板输入条（含附件路径/显示名）→ 主进程 → 宠物窗口 → `client.send('user_message')`。
  这样语音/口型/情绪/行为打断等既有系统**零改动**。
- **形状裁剪注意**：头顶气泡区必须纳入宠物窗口的 interactive rects 上报（否则被 X11 形状裁剪——踩过坑）。

#### 7.5.3 主进程 IPC 契约（bridge `teaching.*`，两个渲染面共用）

渲染侧 API（经 preload；宠物面与黑板面各用其半）：

| API | 方向 | 说明 |
|---|---|---|
| `getState(): Promise<{mode: "normal"/"teaching", folded: boolean}>` | 双向查询 | 当前教学模式状态 |
| `onState(cb)` | 主 → 渲染 | 状态变化订阅（mode/folded 广播） |
| `enter(reason)` / `exit()` | 宠物 → 主 | 请求进入（reason: "menu"/"keyword"/"debug"）/退出教学模式 |
| `mirror(ev: MirrorEvent)` | 宠物 → 主 → 黑板 | 镜像对话事件（见下） |
| `goto(messageId)` | 宠物 → 主 → 黑板 | 点击头顶气泡 → 黑板跳段 |
| `notifyDragStart()` | 宠物 → 主 | 教学模式中拖拽开始 → 触发折叠 |
| `onMirror(cb)` / `onGoto(cb)` | 主 → 黑板 | 黑板侧订阅镜像事件 / 跳转命令 |
| `onVisibility(cb)` | 主 → 黑板 | 展开/折叠/退出命令（黑板播对应窗口动画与视图切换） |
| `requestSend(text, attachments?)` | 黑板 → 主 → 宠物 | 黑板输入条发送（附件只传路径/显示名；宠物窗口执行 WS 发送） |
| `onSendRequest(cb)` | 主 → 宠物 | 黑板输入的接收端（宠物面执行 `client.send('user_message')`） |
| `requestUnfold()` / `requestExit()` | 黑板 → 主 | 角标点击恢复 / 黑板 × 退出 |
| `ready()` | 黑板 → 主 | 渲染就绪（主进程等待后发首批数据） |

`MirrorEvent = {kind:"user_message", text} | {kind:"reply_start", messageId} | {kind:"token", messageId, text} | {kind:"reply_end", messageId, fullText, interrupted} | {kind:"history", messages[]}`

主进程内部职责（编排中心 `electron/teaching/`）：状态机（normal / teaching-expanded / teaching-folded）、窗口生命周期、消息路由、入口接线（托盘菜单 + second-instance 保持不冲突）、折叠/展开/退出动画时序、异常兜底（黑板崩溃 → 自动重建或降级退出教学模式）。

#### 7.5.4 后端配合（第二轮）

- `set_mode {mode}` 事件：进入教学 → `teach`（后端在该连接的 prompt 注入"板书讲师"提示词——输出结构化：标题/要点/步骤/代码块；讲解口语化适配 TTS）；退出 → `normal`。
- 行为引擎暂停：`set_mode: teach` 时该连接不再下发自主行为指令（防讲课中自己溜达）；恢复后续跑。

#### 7.5.5 阶段拆分与验收

| 步 | 内容 | 验收 |
|---|---|---|
| **1（本轮）** | 黑板窗口基础设施 + 模式编排（进入/走位/折叠/恢复/退出/IPC 契约全量） | 说"开始教学"→ 黑板滑入+宠物到位；拖动→折叠成角标；点角标→卷出；"下课"→退出 |
| **2（本轮）** | 流式板书渲染（镜像链路 + Markdown/代码高亮 + 逐字上墙 + 滚动锚点保留）+ 头顶问题气泡 + 黑板输入条 | 提问 → 黑板上逐字板书；点气泡跳段；折叠恢复后滚动位置不丢 |
| **3（下轮）** | 教学提示词（set_mode）+ 教鞭光点/重点高亮 + 恢复衔接表现 | 讲解有"老师"结构感；讲到哪光点到哪；恢复时"上次讲到这" |
| **4（下轮）** | 文件分析（喂文件 → 黑板讲解；路径输入起步，拖拽待验证 X11） | 给它一个文件路径，它开讲 |

**边界**：不引入第三个窗口（角标 = 黑板窗口自身折叠态）；不改 WS 主体连接归属；不改动词/渲染器架构；折叠状态不触发落库/会话切分（同一会话延续）。

### 7.6 设置面板与主题（P4 前置，2026-10-15 决策）

**定位**：BYOK 产品化的关键件——所有人（含非技术用户）拿到安装包后能自己配 LLM、改名、调声音；同时是**首启引导复用基座**（§8.3：首次启动自动打开设置 + 欢迎语）。

#### 7.6.7 窗口 UI 套件（2026-10-18）

**问题**：7 个渲染入口各自一套 CSS（reset/字体/按钮/输入/面板/空态重复），圆角 5–20px 混用，没有共享弹窗与无边框窗口交互层；主题体系已存在但缺少统一消费方。

**目标**：在 `frontend/src/shared/ui/` 建一套窗口样式与外壳组件，所有窗口按需复用；沿用现有 `--ui-*` 主题（不重造配色），本轮先迁移**设置窗 + 黑板**。

- 样式分层（只通过 `ui.css` 的 `@import` 清单接入，不引入拼接脚本）：`base`（作用域 reset/滚动条/焦点环）→ `layout`（应用根/无边框窗口/标题栏/八向缩放/侧栏/工具栏/分区）→ `controls`（按钮/图标按钮/字段/输入/下拉/开关/筛选胶囊）→ `surfaces`（面板/列表/空态/加载/提示条）→ `modal`（遮罩/弹窗）→ `motion`（keyframes + reduced-motion）。

- 静态 token（字体/字号/圆角/动效/焦点环/警告色）加在 `shared/theme/theme.css`，**不进入** `palette.ts` 的 4 色派生契约。
- 无边框窗口交互统一到主进程 `electron/window/frameless.ts`：渲染侧 `WindowTitleBar` / `WindowResizeHandles` 采集手势 → `bridge.frameless.move/resize` → 主进程按 sender 分发。几何只信 `request-bounds` 缓存的**请求值**（fractional DPI 下禁止把 `getBounds()` 的舍入宽高回喂）；最小尺寸/工作区边距/形态记忆/讲台跟随由窗口注册项与 `onBoundsChanged` 回调承担（动画等程序化写入不触发回调）。
- 设置窗保留系统原生标题栏；黑板接入通用引擎（替换原 teaching 专有 resize/move 通道）。
- 后续迁移（不在本次）：提醒列表 → 气泡 → 托盘菜单 → 聊天面板 → 宠物窗拖拽；`ModalShell`/`ResizableModal` 由设置页主题自定义编辑器与确认框接入。

### 7.7 提醒功能 v1（2026-10-18）

**用户路径**：

1. 自然语言创建：“明天上午 9 点提醒我交房租”“20 分钟后提醒我关火”“每天下午 3 点提醒我喝水”；
2. 模型调用 backend 型工具 `create_reminder` → 后端校验/落库 → 聊天区确定性确认
   `已设置提醒 · 明天 09:00 · 交房租`（时间解析错误在设置时即可见）；“动作 + 具体钟点/
   时长”的请求带 `tool_choice` 强制调用（2026-10-18 修复模型只说不做）；网关忽略时回复后
   推警示 notice，不静默假成功；
3. 到点：`proactive{kind:"reminder"}` → 宠物气泡（**与语音开关无关，一定出**）+
   可选 TTS 音频帧（`[reminders].voice`，默认关闭）；同一 tick 到期多条合并为
   一条列表气泡（`items`）；
4. 气泡悬浮条：普通回复是「展开｜✕」，提醒气泡是「知道了｜✕」。点「知道了」= 整批
   已读；不点/60s 自动收起/被替换/点 ✕ → 该批进入**右侧未读列表**（不丢失）；
5. 未读列表：底边踩在聊天输入框上方、横向贴兔子视觉右缘；右侧优先、右侧不够翻左侧、
   两侧都不够用紧凑条「待看 N 条」。折叠只显示**最新 2 条（最新在最下面）**，右上角数字
   可点展开全部，展开后点面板外自动收回；每条未读前有红点；右键菜单「全部已读」；
   底部居中灰点 +「未到时间 N 条」（无灰铃）：点击后顶部固定、向下展开所有未到期计划，
   展开后入口改为「收起」；点面板外/失焦收回；教学/向导/宠物隐藏时列表让位，恢复后重新显示；
   重启后未读仍在；若没有未读、只有未到期计划，窗口缩成常驻灰灯小条（兔子右侧、输入框
   上方约 60px，灰点 +「待办 N」，无框无底色，内容贴向宠物，悬浮提示「存在待办事项」，
   点击向下展开）；灰灯与面板统一用 140px 选边标准，右边放不下面板时一起翻左；
   灰灯 ↔ 面板、未读 ↔ 时钟视图的展开/收回均带缓动动画；
6. 时钟视图：标题「提醒」右侧的“时钟 + 绿点”入口切换；显示当天全部事件（已读 + 未读）+
   所有未到期计划，按到期时间正序，未读红点 / 已读绿点 / 未到期灰点，已读与未到期行不可点；
   点未读行 = 已读；点面板外回到未读视图；没有内容时显示“还没有提醒”；
   向下展开以便 7~9 条一次看全；每项悬浮显示红色 ×，按属性提示“删除已读/未读事项”
   或“移除待办事项”，点击即删对应事件/计划（无二次确认，后端回两份快照收敛）；
7. 查看 / 取消计划：`list_reminders` / `cancel_reminder`（按 id 或文本关键词）；
8. 宠物隐藏 / 教学 / 设置向导中：系统通知兜底，前端排队，环境恢复后补气泡；
   用户离开（系统空闲 ≥2 分钟）即使宠物可见也补系统通知。

**调度与补报**（`application/reminder_service.py`）：

- 每 10s tick（不用长定时器，休眠/改系统时间/重启后自然补上）；
- 同一 tick 到期提醒合并为一个批次，送达成功后逐条写 `reminder_events`（未读）；
- 一次性提醒送达后 `fired`；重复提醒滚动到下一次；
- 错过：一次性补报（`late=true`）；重复超过 5 分钟直接滚到下一次，不补历史；
- 每次 tick 最多处理 `max_catchup` 条（默认 10），一批列在同一气泡；
- 未送达（无宠物连接/发送失败）不标记，下轮重试；
- 连接路由：`hello.client_role="pet"` 才绑定推送通道（设置窗不抢）。

**数据与配置**：`reminders`（计划）+ `reminder_events`（每次触发/已读状态，§6.2）、
`[reminders]` 配置（§6.3）；提醒域 `modules/reminders/` 是两张表的唯一写入方，
application 层只编排。未读列表用 `get_reminders` / `ack_reminders`，时钟视图用
`get_reminder_history`（当天 `fired_at` 事件 + `scheduled` 未到期计划，按 `due_at` 正序返回）。

**边界（v1 不做）**：“稍后提醒”按钮、设置页提醒历史、开机自启、本地确定性
时间解析兜底（当前靠“回显确认 + 后端校验”收敛模型误差）。

### 7.8 记忆本（2026-10-18）

**用户路径**：

1. “记住这个链接，叫我的博客：https://example.com” / “把这两个文件夹都记一下：……” →
   `save_item` 批量保存；没给名字时自动起名并回显（域名/末级目录名），同名再次保存 =
   更新值；`match_forced_tool` 对明确的保存指令强制调用，避免模型只回“记住了”；
2. “打开我的博客” → `open_item(name)`：后端按名字取精确 URL/路径 → 前端
   `shell.openExternal` / `shell.openPath`；临时链接只允许用户本轮消息里出现过的 URL；
   路径条目打开前检查存在性，失效提示“可能被移动/删除，或磁盘没连接”；
3. “我记了些什么？” → `list_items`：通知里列出名字/类型/值/路径状态（失效标 ⚠）；
4. “把‘博客’改名叫‘主页’” → `rename_item`；“忘掉‘博客’” → `delete_item`
   （只删记录，不动磁盘文件；链接/文本这类虚记录可直接删，路径记录要求用户点名）；
5. “把‘项目目录’这个文件夹删了” → `delete_path` → **确认气泡**（精确绝对路径 +
   删除/取消）→ 用户点删除 → 主进程移入回收站 → 前端回传 `memory_book_file_deleted` →
   后端移除记录、清长期记忆、写遗忘名单；
6. 设置 → 记忆本：列表/筛选/新增/打开/改名/删记录；内容列固定单行，放不下时用“…”省略
   （悬停看完整值），避免长链接/路径把行撑高；改名改为整行编辑；路径条目额外提供
   “删除文件（回收站）”，走主进程原生确认框（同样不是永久删除）。

**歧义保护**：路径条目只说“删掉 X”时，后端不猜——返回“只删记忆本记录，还是连
`D:\...` 一起删？”；用户说“从记忆本删掉”才走 `delete_item`，说“把文件夹删了”才走
`delete_path`。链接/文本没有实体，删记录可以直接做。

**失效与更新**：路径在保存时校验存在、每次打开再校验；列表顺手标 ⚠。不做后台文件监听
或全盘搜索——用户移动/删除文件夹后，打开时提示更新路径或删记录。链接不做联网预检，
打开交给浏览器（重定向浏览器自然跟随）；以后可加“体检”工具做 HEAD 检查。

**删除后的“真忘掉”**：删除/更新条目时清掉长期记忆中含同值的条目，并写入 30 天遗忘名单；
后台记忆提取通过注入的 `is_forgotten` 跳过命中项，防止旧对话把已删链接重新提取；
重新保存同一个值会解除遗忘。真实文件删除只进系统回收站，可恢复；v1 不提供永久删除。

### 7.9 联网搜索（2026-10-18）

**用户路径**：

1. “搜一下 DeepSeek V4 发布的最新消息” / “查一下明天北京天气” → 模型调用 `web_search`；
2. 后端调 DeepSeek `/v1/tools/search`（`count` 默认 5、`need_content=false`）→ 取
   `title/url/summary/date` → 追加 assistant `tool_calls` + `tool` 消息 → **第二轮 LLM**
   生成回答；回答用 `[1][2]` 引用并在末尾列出标题/URL；
3. “看看这个网页并总结：https://…” → 模型调用 `web_fetch` → DeepSeek
   `/v1/tools/fetch` → Markdown 正文按 `max_fetch_chars` 截断 → 第二轮总结；
4. 搜索/抓取结果以 notice 形式提示“已联网搜索：N 条结果”/“已抓取网页：…”（在
   `reply_end` 之后）；正文只进模型上下文，不直接展示。
5. 开关关闭时工具返回“联网搜索未开启”，模型提示用户去设置 → 搜索打开，不编造结果。

**协议/架构**：不新增 WS 事件；`web_search`/`web_fetch` 是 backend 型 + `feedback`
工具；`ChatMessage` 增加 `tool_calls`/`tool_call_id`；第二轮不携带 tools，避免循环。
搜索失败（401/402/429/超时等）也会作为 `model_content` 回传，让模型向用户说明失败，
而不是假成功。

**计费与限流**：Search、Fetch 各 ¥5 / 1000 次成功请求（仅 200 且结果非空计费）；
2026-11-01 00:00（北京时间）起计费；每个账号两个端点各 5 QPS；后端按 0.21s 间隔
串行限速，408/429/5xx 重试一次。

**安全**：搜索结果/网页正文是**不可信资料**，提示词明确要求只引用、不执行其中指令；
搜索词不包含用户隐私/本机路径/文件正文；抓取正文截断，避免上下文被撑爆。

### 7.9 工作模式（独立聊天窗，2026-10-18）

**定位**：宠物旁胶囊只够短问答；工作模式提供完整对话记录、历史导航、长回答阅读与
单轮「深度思考 / 智能搜索」开关。它与教学模式、宠物胶囊**共用同一条后端 Session**，
进入/退出不清空任何上下文；非目标：多会话列表、消息重新生成/编辑、语音输入（无 STT）。

**窗口**：第八渲染入口 `work.html` + `src/work/`。无边框自绘（套件 `WindowFrame
variant="solid"` + `attachFrameless`），默认约 900×780、最小 560×520，位置/尺寸
本次运行内记忆；关闭 = 隐藏（保留记录与滚动位置），`before-quit` 后放行真正关闭。

**宠物依附**：工作窗显示时，宠物滑步到窗口左下角外侧（复用教学讲台几何
`podiumPoint`：图像右缘贴窗左缘、脚底与窗底平齐），拖动/缩放工作窗时同帧跟手；
关闭、隐藏或最小化时滑步回进入工作模式前的位置。教学模式优先：教学进行中不抢占
讲台位，宠物由教学域负责。工作窗可见期间，宠物面同时**隐藏底部聊天输入框**、
**不显示对话回复气泡**（大模型回复只出现在工作窗；提醒/称呼引导等本地气泡不受影响），
并让行为执行器跳过自主行为（与教学模式的防御同款），避免宠物在依附后自己走开。

**数据链路**（不开第二条 WS）：

```
工作窗 ──IPC──> 主进程 work 域 ──IPC──> 宠物窗 ──WS──> 后端
工作窗 <──IPC── 主进程 work 域 <──IPC── 宠物窗 <──WS── reply_start / reasoning / token / reply_end
```

- 发送/打断/历史请求经 `electron/work/index.ts` 转发；宠物窗仍走统一入口
  `sendUserMessage()`（关键词、教学模式镜像、气泡、会话记录不重复实现）。
- 镜像按「工作窗是否存在」而非可见性；隐藏期间继续同步。
- token/reasoning 用 25ms `setTimeout` 合批（不用 rAF——窗口隐藏时 rAF 会暂停）。

**可靠性**：工作窗 `ready` 前主进程缓冲事件（上限 500）；发送/历史用 `requestId`
配对 + 8 秒超时，宠物窗重载/崩溃时拒绝所有在途请求；历史采用「单飞 + 序列边界」——
请求后的事件与 `history` 响应一起原子回交，并附 `live` 快照（中途打开工作窗时续上
正在流式的回复）。宠物窗重载会建立新 Session，工作窗收到 `work:pet-ready` 后清空
旧记录重新拉取，不合并。

**协议**：`user_message` 增加可选 `options: {search}` 与 `client_id`
（前端本地消息 id）；新增服务端事件 `reasoning {message_id, text}`（推理增量，不进入
正文/TTS）、`message_saved {client_id, db_id, role}`（落库回执，工作窗按 DB 行 id 删除）、
`message_deleted {id, ok}`、`sources {message_id, items}`（搜索来源结构化信息，工作窗
引用悬浮卡片用）；客户端事件 `delete_message {id}`（当前会话单条删除）。
`load_history` 的 `session_id` 可省略（回填当前连接会话）。

**深度思考（已移除）**：2026-10-19 用户定稿移除该开关——原实现只是同一模型追加
推理提示 + 抬高 `max_tokens`（不切模型），体感弱。若所用网关/模型返回
`delta.reasoning_content`，工作窗仍会折叠展示「已思考（用时 N 秒）」；没有推理增量时
整块隐藏（与开关无关）。

**智能搜索**：`search=false` 只从本轮工具表移除 `web_search` / `web_fetch`，其余工具
（提醒/记忆本/开窗）保留；`search=true` 追加“优先联网核实”的临时 system 提示（不强制
调用）。

**UI**：用户消息右气泡、助手消息左 Markdown（复用 `src/board/markdown.ts` 与
`shared/markdown/markdown.css`）；右侧导航每条用户提问一个刻度（滚动高亮、hover
预览、点击滚动 + 闪烁）；输入条为自增高 textarea（Enter 发送 / Shift+Enter 换行），
附件复用 `modules/chat/file-support.ts` 的类型快筛。

**消息时间与操作**（2026-10-18）：每条消息底部**常显** `YYYY-MM-DD HH:mm`（历史用
`created_at`，实时用户用发送时间、助手用开始回复时间；助手落库时也写开始时间，保证
刷新前后一致）。鼠标悬浮消息时出现「复制 / 删除」；右键菜单为「复制全文 / 复制选中
（无选区禁用）/ 删除此消息」。复制走 Electron 剪贴板；助手复制 Markdown 源文，用户
复制纯文本。**删除只删单条**（用户定稿，不删整轮）：历史行 id 直接可用，实时消息经
`message_saved` 回执挂上 DB 行 id；流式中的回答暂不可删。后端 `delete_message` 只接受
当前会话的 id，删除 SQLite 行后 `Session.reload_history()` 重建注入 LLM 的内存上下文，
保证模型下一轮不再看到它；刷新/重开不会复活。删提问会留下孤立的回答（反之亦然），
这是“不删整轮”的既定语义；已经写入长期记忆的内容不回溯删除。

**正文链接**：搜索结果里的 `[n]` 角标会自动映射到同一条消息「来源」列表里的 URL
（跳过代码块/行内代码/已有链接），变成可点击链接；来源列表兼容 `[n] …`、`1. …`、
`1) …`、`1、…` 等写法。工作窗与教学黑板共用同一套 `renderMarkdownWithCitations`。
点击后在**本窗口内嵌浏览器**打开；悬浮在引用/来源链接上会显示来源卡片（favicon、
站点名、日期、标题、摘要、URL）。摘要不在正文里：后端的搜索结果带 `sources`
结构化字段，经 `sources {message_id, items}` 事件随回复下发；前端按 URL 匹配，
历史消息没有该事件时回退到来源行里的标题/日期。

**内嵌浏览器（2026-10-18）**：标题栏内嵌「对话 + 链接标签」。本窗口链接点击后由主进程
创建 `WebContentsView` 打开，整页切换（聊天正文/输入条 `display:none` 保留 DOM 与滚动位置）；
工具条提供后退/前进/刷新/系统浏览器；标签名优先页面标题、加载中先用域名；标签过多折叠为
`+N ▾` 下拉。每个标签独立 `WebContentsView`，共享**临时会话**（无 `persist:`，关闭应用
不留 Cookie）；无 preload/Node、sandbox、权限全拒、下载拦截；最多 6 个标签，超出关闭最旧的
非当前标签。视图 bounds = 标题栏 40 + 工具条 34 下方、四周留 8px（保住窗口圆角与四边缩放
热区）。页面内链接由注入脚本转成 `window.open(..., '_blank')`，统一进入新标签。

## 8. 打包与发布

### 8.1 构建产物

| 平台 | 前端产物 | 后端产物 | 安装包 |
|---|---|---|---|
| Windows | electron-vite build | PyInstaller onedir `backend.exe` | NSIS（electron-builder） |
| Linux | 同上 | PyInstaller onedir | AppImage + deb |
| macOS（远期） | 同上 | PyInstaller onedir | dmg（electron-builder） |

后端产物作为 `extraResources` 打进 Electron 安装包（`resources/backend/`）。

### 8.2 打包注意

- **PyInstaller**：onedir 模式（启动快于 onefile）；uvicorn 程序化启动（禁 reload）；收集 uvicorn/asgi 的 hidden imports；Windows 下可能触发杀软误报 → 备忘：后期考虑代码签名。
- **构建机约束**：PyInstaller 不支持交叉编译，各平台包必须在本平台构建 → **GitHub Actions 构建矩阵**（`windows-latest` + `ubuntu-latest`；未来启用 macOS 时加 `macos-latest` 一行），一次 tag 出全部产物。
- **macOS 分发门槛（远期备忘）**：必须 Apple 开发者账号（$99/年）+ 代码签名 + 公证（notarization），否则用户无法直接打开；成本决策留到启用时评估，架构侧无需改动。
- **自动更新**：electron-updater（NSIS / AppImage 均支持）；更新后前后端同步替换（同一个安装包，天然一致）。
- **版本握手**：`package.json.version` = 后端 `__version__`；WS `hello` 携带双方版本，不一致时明确报错（防用户只替换了单个二进制）。

### 8.3 首启引导（产品化必需）

首次启动向导：① 选择服务商（presets 下拉）→ ② 填 key → ③ "测试连接"（`test_llm`）→ ④ 完成（可选：下载/导入 Live2D 模型）。
